# S4E09 storyboard

1. **01 · Question** — Start with one bounded question — Write the symbol, session, lens, and output before opening a recipe; a packet should be challengeable. — visual: `s4e09-question`
2. **02 · Recipe** — Name the recipe fields — Fix universe, filters, denominator, freshness line, and invalidation rule so the next run is comparable. — visual: `s4e09-recipe`
3. **03 · Inputs** — Attach inspectable inputs — Keep the exact symbol set, contract scope, source lens, and selected date beside the recipe. — visual: `s4e09-inputs`
4. **04 · Ownership** — Make ownership explicit — A reviewer challenges the read, a maintainer preserves lineage, and a runner records the next pass. — visual: `s4e09-owner`
5. **05 · Run** — Run the packet without editing the question — Cookbooks should make the same method easy to rerun; a new timestamp is not permission to change the boundary. — visual: `s4e09-run`
6. **06 · Record** — Record result and missingness — Save observed fields, unknowns, exclusions, and the next check instead of filling gaps with confidence. — visual: `s4e09-record`
7. **07 · Challenge** — Leave a challenge path — A packet is useful when another analyst can inspect the inputs, replay the run, and lower a claim cleanly. — visual: `s4e09-challenge`
8. **08 · Practice** — Hand the packet to Market Recap — Next: S4E10 · turn a completed packet into a grounded Market Recap with vetted charts and explicit caveats. — visual: `s4e09-outro`
