# S3E19 storyboard

1. **01 · Record** — Write the method change — Name the repair question, changed field, recipe version, and date before publishing a new interpretation. — visual: `s3e19-record`
2. **02 · Diff** — Show what changed — Compare prior and current packet fields so another analyst can see the smallest change that moved forward. — visual: `s3e19-diff`
3. **03 · History** — Keep the prior cohort intact — Link the new method to future rows only; never replace a published read with a later version. — visual: `s3e19-history`
4. **04 · Scope** — Declare the next boundary — State eligible rows, freshness, required fields, invalidations, and the exact cohort window before intake. — visual: `s3e19-scope`
5. **05 · Evidence** — Attach the validation path — Include blind review, rerun instructions, resolution vocabulary, and the owner who can challenge the packet. — visual: `s3e19-evidence`
6. **06 · Disclosure** — Publish the remaining gaps — Keep missingness, stale context, unresolved checks, and limited rows visible beside the method change. — visual: `s3e19-gaps`
7. **07 · Ownership** — Sign the release — Make reviewer, maintainer, replay operator, and escalation path accountable for the next cohort. — visual: `s3e19-owner`
8. **08 · Practice** — Open the season audit — Next: S3E20 · run a season-level audit of method changes and unresolved gaps without turning process into performance. — visual: `s3e19-outro`
